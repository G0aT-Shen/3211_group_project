On 11 October 2026, DeepSeek Harness (DeepSeek) audited the search layer for the group after an external report that the project contained at least one bug. Three defects were reproduced with regression tests that failed against the audited revision: (1) a fully quoted search expression was replaced by its shlex-decoded token, so the expression inside the documented outer quote pair was shell-decoded twice, and the quoted form silently selected different records than the direct form for values containing backslash escapes such as Windows-style paths; (2) model/search.py tokenized words with the Unicode-aware \s while shlex and the command parser separate only on space, tab, CR and LF, so text stored as one word (for example containing a non-breaking or ideographic space) could not be found by the same unquoted literal; (3) parse_datetime accepted non-ASCII decimal digits for the year because strptime's %Y matches \d, although DR-01 defines only the ASCII YYYY-MM-DD pattern. The fixes keep the optional outer quote pair a pure container that is removed without decoding, use the POSIX separator set in the search tokenizer, and enforce the ASCII timestamp pattern before strptime. tests/test_audit_regressions.py reproduced all three defects before the fixes (19 failing assertions on the audited revision) and passes after them; the quoting interpretation was confirmed with the project owner rather than assumed. One intermediate scratch probe from this audit was discarded as vacuous because it skipped every generated case, so the retained evidence is limited to the regression tests, the documented-example sweep and randomized checks that actually assert results. On 12 October 2026, DeepSeek Harness (DeepSeek) audited the working tree again for value-boundary defects. One product defect was reproduced and fixed. The command parser and the search tokenizer trimmed the command line and the search expression with str.strip, which removes every Unicode whitespace character, while docs/design.md fixes the word model to the POSIX shell set (space, tab, CR, LF) exactly like shlex. A value whose last character was whitespace outside that set (for example an ideographic or non-breaking space, common in CJK input and in pasted text) was therefore silently shortened by add and edit, and an unquoted search for the same literal silently selected a record that merely prefixed it; measured with records "a" and "a<U+3000>", the criterion text = a<U+3000> returned the record "a". Both layers now strip only the four POSIX separators, and the command parser's outer-quote detection uses the same set so a character left outside the pair is not discarded. tests/test_value_preservation.py reproduced the defect before the fix (51 failing assertions across 9 tests, exit 1) and passes after it. The same session found that the PTY recording test errors on hosts that deny PTY allocation (os.openpty raises EPERM for /dev/ptmx; observed on Python 3.9.6 and 3.12.14), which turns the documented unittest discover command and tools/check_coverage.py into a 1-error run that exits 1; the later review restored that test to the content the project already had, so the error is reported as an environment limitation instead of being worked around inside the test. No other reproducible product defect was confirmed: a 120,000-command CLI fuzz, a 200,000-case search/date parse fuzz, 1,500 randomized sessions with state/ID/persistence/dirty invariants, 3,000 randomly generated condition trees checked against an independent evaluator, a 10,867-line before/after differential against the pre-optimization revision, a 61-case documented-input sweep and a documented-example sweep produced no non-domain exception, no contract deviation and no state or data change beyond the three search-layer fixes of 11 October.
